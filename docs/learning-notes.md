# 实现复盘

## 为什么执行前校验所有步骤

只在执行到某一步时校验，会导致前面的 HTTP 请求已经发出，后面才发现 ID 重复或引用不存在。FlowLoader 在运行前检查整个定义；测试用请求计数证明：末尾存在无效引用时，前面的请求也不会执行。

动态 URL 和请求头需要依赖实际输出，因此仍在发送前二次校验。这是静态校验的边界，而不是对外部服务可用性的保证。

## 为什么 stdout 和 stderr 必须分开

终端用户希望看到进度，脚本调用方希望获得结构化结果。Reporter 在普通模式逐步显示输出，在 JSON 模式收集结果后输出单个对象。失败对象只写入 stderr，并通过非零退出码报告失败。

## 一次实际发现的超时问题

初版为 HttpRequest 设置 timeout，测试覆盖了服务迟迟不发响应头的场景。但审查发现：响应头已返回、正文继续等待时，Java 21 的该超时不能保证完整操作按时结束。

新增回归场景：服务立即发送响应头和首字节，等待 2.5 秒再发送余下正文；客户端设置 1 秒超时。初版错误地成功返回。修复为等待完整 `sendAsync` future，并设置总等待时间，超时取消请求；执行器使用 `shutdownNow` 释放客户端，避免关闭时继续等待。

这里学习的不是“设置一个 timeout 参数”，而是确定它约束的生命周期，并用真实服务测试边界。

## 引用替换的边界

最初用固定字符串替代 URL 引用来预校验。这会将 `${base.output}` 误判为没有协议的 URL，也无法表达动态端口。最终方案是在校验阶段检查引用目标，在执行阶段验证插值后的完整 URI。

替换使用 Matcher.quoteReplacement，避免输出中的 `$` 或反斜杠被解释为正则替换语法；不递归替换，防止响应正文变成新的表达式。

## 建议自行完成的下一次练习

1. 为 HTTP 响应添加字节上限，分别测试 Content-Length 与分块响应。
2. 为输出添加 JSON 字段选择，先定义字段不存在时的行为。
3. 加入重试时区分 GET 与 POST，解释重复请求产生的副作用。

每次练习保留真实的失败测试、修复提交与取舍说明，不把规划中的能力写成已完成成果。
